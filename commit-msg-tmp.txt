Reach directives from the AST and fix source-line mapping (110 tests)

Follow-up to the veloct-markdown commit. Three problems that would have blocked
every downstream consumer:

1. Directives never reached the AST. The scanner removes them from the body
   before CommonMark runs, and nothing merged them back, so an article's
   knowledgeref directives were invisible to reference resolution and the
   reference-list generation that handoff.md 9.4 requires. They are now merged
   back at their source position, which also keeps the author's ordering.

2. Directive spans were reported relative to the body while every other node's
   span is a file line. A diagnostic on a directive in a file with frontmatter
   would have pointed at the wrong line. Spans are now translated to file lines,
   and a test pins the exact lines for a document with frontmatter.

3. The residual offset map was derived from the body's own line numbering, but
   the residual is shorter than the body by however many directive and marker
   lines were removed. In a file containing a directive, every source span after
   it drifted. The map is now built from the lines that actually produced a
   residual line, and a test reconstructs the residual from that map and asserts
   it matches what the scanner produced, so the two cannot silently diverge.

Also adds tests for a container directive's span, an image directive reaching the
AST as a placeholder (never a file, per handoff.md 8.1), and the line a directive
is compared against during the merge.
