Implement veloct-storage: the schema, migrations and rebuildable index (38 tests)

Completes handoff.md 2.4, 20.1 and 22, plus docs/spec/01-data-model.md 3: the v1
schema, a migration story that can be re-run and reports its version, and the
derived content index that Markdown can always rebuild.

What is here:

- migrations.rs: the complete v1 schema as one versioned migration, with the
  version held in SQLite's user_version rather than a bookkeeping table that can
  drift from reality. MIGRATION_COUNT is checked against CURRENT_SCHEMA_VERSION by
  a test, so appending a migration without bumping the constant fails the build
  instead of shipping. A database written by a NEWER Veloct is refused with an
  explanatory error rather than being treated as up to date.
- db.rs: WAL, foreign keys ON, a busy timeout. Before a migration touches an
  existing file it is copied to a timestamped sibling, because a user's
  configuration and release index live only there (an index can be rebuilt from
  Markdown; that cannot).
- models.rs: the status machines from docs/spec/01-data-model.md 6 as closed enums
  with checked conversion, so a typo in the database surfaces instead of silently
  becoming the first variant. Attachment state is three independent axes per
  handoff.md 13.2.1, and AttachmentRow::is_safe_orphan encodes 13.2.4 (referenced,
  queued, in-flight or retry-pending files are never cleanable).
- rebuild.rs: wipe and rebuild the derived index in one transaction, with a
  canonical row order so two rebuilds of the same content are byte-identical. That
  is what handoff.md 14.9 needs from a release comparison, and it is test-matrix
  row E1.

Deliberate choices worth noting:

- A rebuild is scoped to the three derived tables. site_config, deploy_targets,
  releases, attachments and backups share this database and are asserted to
  survive a wipe.
- roll_up_logical_status distinguishes Partial from Failed and from Succeeded, and
  treats Skipped as neither success nor failure, so handoff.md 14.12's "main OK,
  works failed" cannot be reported as a clean success or a total failure.
- A test scans every column name in the schema and rejects anything that looks
  like a stored secret value, allowing only descriptors such as credential_ref and
  secret_scan_status. handoff.md 12 is a schema property, so it is tested as one.
