# Veloct — Test traceability matrix

> `handoff.md` §23, §24, §25 and §28 define behaviours that **must** be covered by automated
> tests. This file is the authoritative map from contract clause → concrete test, and it is
> the checklist used to decide whether the project is "complete". A clause with no test is an
> open work item, not a finished feature.

Legend: **P** = planned, **I** = implemented, **F** = failing (regression).

## I. Honesty rule applied to this matrix

A row may only move to **I** when its test exists **and** passes in the recorded verification
command. Integration points that depend on third-party services Veloct cannot authenticate
against (Cloudflare, EdgeOne, Lsky, S3, GitHub) are tested against a **local fake server**
implementing the documented protocol, and the test name must say so, e.g.
`deploy::cloudflare_upload_against_fake_api`. Vendor behaviour that was never verified against
a live endpoint stays marked `UNVERIFIED` in the matrix and in the UI.

Two consequences the §13 rows below made explicit, because a row can otherwise read as more than
it proves:

- **A row whose test is a frontend test names `cmd /c "npm.cmd run test:ui"` as its command**, not
  a cargo one. This repository has no React test renderer on purpose, so a rule that lives in JSX
  is a rule nothing checks: the storage-target form's decisions live in
  `src/lib/storageTargetForm.ts` and are asserted there, and what the component DOES with them is
  covered by `npm.cmd run build:ui` (tsc under `noUncheckedIndexedAccess` and
  `exactOptionalPropertyTypes`) plus a grep for the call site. A row that needed a rendered
  assertion would not be `I`.
- **A row may state a LIMIT and still be `I`** when the test it names exists and passes and the
  limit is something that test does not claim. "**Stated limit**" in a row means exactly that: the
  behaviour is asserted by inspection or at another layer, the row says which, and it does not
  imply coverage it does not have.

**Where a row's command lives.** The command is the recorded run in §J that covers the row — a row
is never moved on a run that is not written down there. The §13 rows this round added are covered
by two runs: `D130`–`D138` by the snapshot taken while the change set was uncommitted, and `D139`–`D140`
(plus every row above them) by **the run at commit `2496604`**, the newest and authoritative one. A
future row that cannot point at a recorded run is a row that has not moved.
