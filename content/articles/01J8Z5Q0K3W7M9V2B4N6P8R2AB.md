# 不可循环的 Release 模型

`release.json` 在 commit **之前**生成，因此它不能包含自己的 commit SHA。Release 的真相是
`release.json` + Git tag `release/<release-id>` + tag 指向的 commit 三者。

## 为什么 fingerprint 要冻结

同一个 Release 的每个部署子目标必须收到完全相同的 `build_fingerprint`。历史版本重发时按其
tag 与冻结的 snapshot 精确重建，不能混入当前工作区的新修改。

## 部署目标

| 逻辑目标 | main | works |
| --- | --- | --- |
| Cloudflare Pages | 主站项目 | Works Origin 项目 |
| EdgeOne · 中国大陆 | 主站 | Works |
| EdgeOne · 国际 | 主站 | Works |

一个逻辑目标可以「部分成功」：主站成功、作品失败时，成功部分不会被撤回。

:::note{title="为什么 EdgeOne 目前是手动目标" type="warning"}
在拿到可验证的上传 API 之前，EdgeOne 作为导出型目标实现：可勾选、生成完全一致的载荷、
明确标注为手动上传，而不是伪造一个会自动成功的接口。
:::
